# Pull Request Guide

## När ska PR skapas?
- När en issue är färdig enligt DoD
- Mindre PR är bättre än stora, svårlästa
  
## PR-checklista
	1. Titel: tydlig och kort (ex: Feature: Add endpoint editor form)
	2. Beskrivning:
		- Vilken issue åtgärdas
		- Kort beskrivning av lösning
		- Eventuella kända begränsningar eller TODOs
	3. Screenshots / GIF (frontend-funktioner)
	4. Testinstruktioner
	5. Reviewer-uppgifter
		- Kontrollera DoD-kriterier
		- Kontrollera att ingen befintlig funktionalitet bryts
		- Testa scenarier och edge cases
    
## Review-process
- Minst 1 reviewer innan merge
- Kommentarer adresseras innan merge
  
## Tips för studenter
- Små PR underlättar snabbare feedback
- Lägg alltid till tests / previews när möjligt
